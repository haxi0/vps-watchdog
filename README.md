# Watchdog для прерываемых виртуальных машин в Яндекс Облаке

Автоматический watchdog для прерываемых и обычных виртуальных машин (ВМ) в Яндекс Облаке. Watchdog периодически проверяет доступность VPS через ICMP (ping) и при обнаружении недоступности автоматически запускает виртуальную машину с помощью API Яндекс Облака.

Работает в контейнере Docker и использует сервисный аккаунт с JWT для аутентификации, что исключает необходимость ручного обновления IAM токена.

---

## Обзор возможностей

- Автоматический запуск ВМ при недоступности
- Проверка доступности через ping (ICMP)
- Аутентификация через сервисный аккаунт и JWT
- Запуск в Docker / Docker Compose
- Все параметры настраиваются через `.env`
- Минимум зависимостей, не требует cron или systemd

---

## Требования

- Docker 20+  
- Docker Compose v2  
- Аккаунт в Яндекс Облаке с правами администратора  
- Сервисный аккаунт с правами управления ВМ  
- Установленный CLI `yc` (для настройки сервисного аккаунта)

## Установка и настройка в Яндекс Облаке

### 1. Установка CLI `yc`

Если у вас еще не установлен CLI Яндекс Облака, установите его, следуя инструкции:

```bash
curl https://storage.yandexcloud.net/yandexcloud-yc/install.sh | bash
```

После установки перезапустите терминал или выполните:

```bash
source ~/.bashrc
```

Проверьте установку:

```bash
yc --version
```

### 2. Инициализация CLI и вход в аккаунт

Выполните инициализацию и авторизацию:

```bash
yc init
```

Следуйте инструкциям мастера, выберите нужный аккаунт и каталог (folder), где будут создаваться ресурсы.

### 3. Создание сервисного аккаунта

Создайте сервисный аккаунт, который будет использоваться для аутентификации:

```bash
yc iam service-account create --name vps-watchdog --description "Watchdog for VM restart"
```

Запомните или сохраните ID созданного сервисного аккаунта (например, `sa-xxxxxx`).

### 4. Назначение прав сервисному аккаунту

Для управления виртуальными машинами сервисному аккаунту необходимо назначить роль `compute.admin` в нужном каталоге (folder).

Получите ID каталога, если не знаете:

```bash
yc resource-manager folder list
```

Назначьте роль:

```bash
yc resource-manager folder add-access-binding <FOLDER_ID> \
  --role compute.admin \
  --subject serviceAccount:<SERVICE_ACCOUNT_ID>
```

Где:

- `<FOLDER_ID>` — ID каталога Яндекс Облака  
- `<SERVICE_ACCOUNT_ID>` — ID сервисного аккаунта, например `sa-xxxxxx`

### 5. Создание ключа сервисного аккаунта

Создайте ключ для сервисного аккаунта, который понадобится для аутентификации в контейнере:

```bash
yc iam key create \
  --service-account-id <SERVICE_ACCOUNT_ID> \
  --output sa-key.json
```

Файл `sa-key.json` содержит приватный ключ и используется для генерации JWT токенов внутри контейнера. Этот файл является постоянным и не требует обновления.

## Настройка проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com/D4nilKO/vps-watchdog.git && cd vps-watchdog
```

### 2. Создание и редактирование файла `.env`

Скопируйте пример файла `.env.example` в `.env`:

```bash
cp .env.example .env
```

Отредактируйте `.env`, указав параметры вашего VPS и ВМ.

Пример содержимого `.env` с пояснениями:

```
# IP адрес или DNS имя вашего VPS, который будет пинговаться
VM_HOST=1.2.3.4

# ID виртуальной машины в Яндекс Облаке, которую нужно запускать
INSTANCE_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# Интервал между проверками доступности (в секундах)
CHECK_INTERVAL=30

# Количество попыток пинга перед признанием сервера недоступным
PING_ATTEMPTS=3

# Таймаут ожидания ответа ping (в секундах)
PING_TIMEOUT=1

# Путь к ключу сервисного аккаунта (относительно контейнера)
SA_KEY_PATH=/app/sa-key.json

# Идентификатор каталога (folder ID) в Яндекс Облаке
FOLDER_ID=your-folder-id

# Идентификатор облака (cloud ID) в Яндекс Облаке (необязательно, если используется по умолчанию)
CLOUD_ID=your-cloud-id
```

### 3. Размещение ключа сервисного аккаунта

Поместите файл `sa-key.json` рядом с `docker-compose.yml`:

```bash
cp /root/yandex-cloud/sa-key.json /root/vps-watchdog/
```

Структура папки:

```
vps-watchdog/
├── sa-key.json
├── docker-compose.yml
├── .env
└── ...
```

## Как работает алгоритм мониторинга

1. Контейнер в цикле с интервалом `CHECK_INTERVAL` секунд выполняет серию ping запросов к адресу `VM_HOST`.
2. Если все попытки пинга (по количеству `PING_ATTEMPTS`) неудачны, сервер считается недоступным.
3. В таком случае watchdog аутентифицируется в Яндекс Облаке с помощью сервисного аккаунта и JWT.
4. Отправляется запрос к Compute API для запуска виртуальной машины:

   ```
   POST /compute/v1/instances/{instance_id}:start
   ```

5. Если запрос успешен, виртуальная машина запускается.
6. Цикл повторяется, обеспечивая постоянный мониторинг и автоматический запуск.

## Использование

### Фрагмент `docker-compose.yml`

```yaml
services:
  vps-watchdog:
    build: .
    container_name: vps-watchdog
    restart: unless-stopped
    env_file:
      - .env
    volumes:
      - ./sa-key.json:/app/sa-key.json:ro
```

> Ключ сервисного аккаунта монтируется в контейнер только для чтения и не копируется внутрь образа.

### Dockerfile

Рекомендуемая версия:

```dockerfile
FROM python:3.12-slim

WORKDIR /app

RUN apt-get update \
    && apt-get install -y iputils-ping \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY monitor.py .
COPY iam.py .

CMD ["python", "monitor.py"]
```

## Типичные проблемы и отладка

- **Ping не проходит, но сервер доступен по SSH/HTTP**  
  Некоторые VPS могут блокировать ICMP. В этом случае рекомендуется использовать альтернативные проверки (например, TCP порт), которые можно добавить в будущих версиях или кидайте PR.

- **Watchdog не запускает ВМ**  
  Проверьте корректность настроек в `.env`, особенно `INSTANCE_ID` и права сервисного аккаунта. Убедитесь, что сервисный аккаунт имеет роль `compute.admin` в нужном каталоге.

- **Проблемы с аутентификацией**  
  Убедитесь, что файл `sa-key.json` корректный и доступен контейнеру. Проверьте правильность монтирования volume.

- **Логи пустые или отсутствуют**  
  Проверьте, что контейнер запущен и не выходит с ошибкой. Используйте `docker compose logs` для просмотра подробностей.

- **Частые перезапуски ВМ**  
  Watchdog запускает ВМ при каждой недоступности, даже если она уже запускается. Это нормальное поведение, Compute API корректно обрабатывает повторные запросы.

## Безопасность

- Файл `sa-key.json` не включается в Docker-образ, а монтируется как volume только для чтения.
- Храните ключ сервисного аккаунта в безопасном месте и не публикуйте его.
- Используйте отдельный сервисный аккаунт с минимально необходимыми правами.
